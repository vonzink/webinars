# Calculator Integration Map v1.0

Every calculator is a teaching instrument. It should appear only after the audience understands the question it answers.

| Calculator | Slide | Question It Answers | Live Slot | Static Fallback |
|---|---:|---|---|---|
| Rent vs Buy | 006-007 | Is buying worth comparing right now? | Embedded calculator or browser link in a framed MSFG calculator panel | Break-even timeline with example numbers |
| Payment Calculator | 010-011 | What does this price become monthly? | Integrated payment tool with price, rate, down payment, taxes, insurance | Three scenario cards: lower price, base case, higher rate |
| Affordability Calculator | 015-016 | What is approved vs comfortable? | Calculator with income, debt, savings, target payment | Two-number gap slide: lender ceiling vs life-ready number |
| Monthly Budget | 017-018 | Can this payment fit my real month? | Budget worksheet with remaining-room meter | Static budget dashboard with comfort zones |

| Interest Rate Buydown | 032-033 | When does paying upfront make sense? | Buydown tool showing cost, savings, break-even | Cost divided by savings formula plus timeline |

## Placement Rules

- The live calculator should never be the first thing on a topic.
- Each calculator gets a setup slide, a live demo slide, and a one-sentence takeaway before transition.
- Any external calculator link should open in a clean presenter browser or embedded iframe area styled as an MSFG calculator panel.
- Keep all demo numbers hypothetical unless approved for the delivery date.
- Do not show rate quotes without compliance review.

## Placeholder Contract

Each live calculator placeholder should include:

- Tool name
- Question answered
- Inputs expected
- Output to watch
- Fallback slide reference
- Compliance note when payment, rate, APR, or cost appears
